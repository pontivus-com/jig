# Jig 1.0.6 — release notes

**Status:** Final release notes for Jig v1.0.6.  
**Target tag:** `v1.0.6`

Jig 1.0.6 is a presentation/browser patch over v1.0.5. It improves secondary-screen reading geometry, adds a curated multi-theme application system, makes Jig branding follow the active theme, and standardizes reminders on browser/OS Notification delivery without changing Jig's canonical Task, persistence, HTTP, repository or Git synchronization semantics.

## Continuous History and Settings measure

History and Settings now own one continuous centered maximum content measure of 50rem (approximately 800px) whenever space permits.

That reading/configuration measure is independent of Planner's 73rem semantic composition breakpoint:

- 1440, 1168, 1167, 1024, 900 and 800px viewports retain the approximately 800px cap;
- narrower viewports naturally consume the available width;
- crossing 1168→1167px no longer makes secondary content expand discontinuously;
- Planner remains full-width/full-bleed;
- Settings' two-column→one-column reflow remains independently owned by the existing 73rem layout boundary.

## Curated application themes

Settings → Appearance now separates two independent presentation choices:

- **Theme** — one of exactly 13 governed application themes;
- **Appearance** — `System | Light | Dark`.

The shipped theme catalogue is:

- Jig;
- Astryx Neutral, Butter, Chocolate, Matcha, Stone and Y2K;
- Gruvbox, Dracula, Solarized, Nord, Catppuccin and Tokyo Night.

Every selectable theme supports the same Light/Dark/System behavior through the single root Astryx `Theme` owner. System follows the browser/platform color preference without a second JavaScript color-mode engine.

Pinned Astryx Gothic 0.7.13 is explicitly dark-only upstream and is intentionally **not** selectable in v1.0.6. Architectural review removed an earlier non-governed Gothic adaptation so the released implementation matches JIG-106-FR-02 and `AGENTS.md` exactly rather than changing authority to justify implementation.

Community theme palette provenance and licensing are recorded in `THIRD_PARTY_NOTICES.md`.

## Complete semantic theming

Theme selection applies to the application semantic contract rather than only swapping an accent color.

The active theme owns representative roles for:

- application/body, surface, card, popover and muted backgrounds;
- primary/secondary/disabled text and icons;
- borders, focus and interaction overlays;
- current day;
- Task selection and elevation;
- drag/drop state;
- priority cues;
- success/warning/error/information status;
- navigation state.

Combined state precedence remains invariant: focus remains independently visible, drag owns transient interaction state, selection owns persistent selected state, and priority retains its leading semantic cue.

## Theme-aware Jig wordmark

The application header now uses one canonical inline Jig wordmark geometry.

Its primary mark and alignment pin consume active semantic brand roles, so the in-application logo follows the selected theme and Light/Dark resolution without maintaining separate per-theme logo assets. Fixed favicon, application icon and release/README artwork remain theme-independent static brand assets.

## Browser Notification-only reminders

Due reminders now use one browser/OS Notification channel while Jig is open and Notification permission is granted.

Visibility and focus no longer select between an in-app Toast and Notification:

- visible/focused → browser Notification;
- visible/unfocused → browser Notification;
- hidden/open → browser Notification;
- default/denied/unsupported permission → no claimed delivery;
- constructor failure remains retryable while the reminder is eligible;
- successful delivery keys suppress duplicates.

There is no reminder Toast fallback, service worker, push service or closed-browser delivery guarantee.

Notification permission remains an explicit Settings action and continues to be owned by the browser/OS.

## Settings owns appearance configuration

Theme and Appearance controls exist only in Settings → Appearance.

Planner, the header, History, Task cards, Task workspace and Task menus do not receive theme setters or theme-specific props. Changing presentation does not mutate canonical Task data, Planner state, persistence, protocol or Git synchronization state.

## Architecture preservation

The v1.0.6 implementation was explicitly reviewed against `AGENTS.md` before release.

The final implementation preserves:

- functional-core / imperative-shell direction;
- one canonical Task/planning authority;
- no changes under the Task core, shell/protocol or Git synchronization authorities for this release;
- one typed theme registry and one root Astryx Theme owner;
- public Astryx components/theme APIs only;
- pinned `@astryxdesign/cli@0.7.13` generated theme artifacts with drift checking;
- strict TypeScript typing;
- no DTO/ViewModel hierarchy;
- no service/repository/workflow abstraction stack;
- no private Astryx selectors/custom properties, `!important`, feature-level theme branching or second theme engine.

A permanent architecture test also rejects reintroduction of the non-governed Gothic preset into the v1.0.6 registry, theme build manifest, stylesheet imports or dependency graph.
