# Jig 1.1.2 — release notes

**Status:** Final release notes for Jig v1.1.2.  
**Target tag:** `v1.1.2`

Jig 1.1.2 is a corrective patch over v1.1.1. It closes the v1.1.2 corrective campaign tracked in issue #66 and publishes the implementation certified through PR #67, followed by the release-tail governance hardening in PR #68.

## Synchronization continuity and diagnostics

Jig now exposes structured, credential-free synchronization diagnostics covering phase, classified failure, observed heads/lineage, retry state and recovery outcome.

For provably related Jig-owned `jig-data` histories, Jig can perform one bounded automatic reconciliation without force-pushing or touching unrelated repository state. The complete resulting planning snapshot must pass canonical validation before an authoritative ref is moved.

When that proven-safe domain reaches an eligible same-dataset semantic conflict, Linux/Desktop and Android share the governed **Resolve sync conflict** workflow. The user chooses complete local/remote Task or recurrence-family records and explicitly reviews affected-date ordering before one validated candidate is accepted.

Unsafe ancestry, incompatible datasets or snapshots, ambiguous remotes, rewrites and unrelated history remain non-destructive **Needs attention** states. Jig does not become a general Git merge/rebase/conflict product.

The historical ordinary Desktop synchronization concern was not reproduced by the permanent upgraded reproduction. The campaign therefore closed that item as **NO DEFECT REPRODUCED / NO CAUSAL FIX REQUIRED**; this release does not claim a speculative ordinary-sync fix.

## Presentation and interaction corrections

The release corrects the governed desktop/narrow presentation and interaction surfaces:

- distinct application chrome, Planner/day canvas and Task-card surface roles across all 13 governed themes in Light and Dark;
- Astryx AppShell main restored as the sole configured page-scroll/fill owner;
- Task movement uses the real shared Task-card DragOverlay plus React-owned card-sized prospective placement rather than insertion lines;
- pointer/touch activation, same-date/cross-date/empty-date placement, cancellation and persisted final position remain on the single pinned dnd-kit path with optimistic DOM sorting disabled;
- desktop transient/durable feedback and narrow snackbar/inline attention use viewport-appropriate placement while sharing one semantic feedback state;
- normal application motion uses the governed shared Astryx/Jig duration-token scale while reduced-motion remains authoritative.

## Architecture and Android continuity

The corrective campaign also tightened source ownership:

- portable semantics live under `src/core`;
- runtime envelopes live under `src/protocol`;
- shared GitHub provider code lives under `src/github`;
- Linux system-Git effects are split under focused `src/shell/git/**` owners;
- recovery policy remains singular in the functional core without DTO/service/repository duplication.

Android semantic-conflict entry now exports a pending local portable snapshot before remote-ahead classification so true related divergence can reach the same governed resolver. Certification uses a stable non-production signing identity and proves in-place API-24 update preservation without uninstalling or clearing app-private state.

## Certification

The v1.1.2 implementation closure ledger records PASS across the hosted type/architecture/theme gates, core/integration tests, real-browser acceptance, permanent repository-capable Git/recovery matrix, Android build/static/FLOSS/version/F-Droid checks, API-24 instrumentation, Android in-place update preservation, required native-host evidence and the replacement governed visual audit.

Visual certification uses the canonical desktop/narrow evidence matrix and closed all identified blocker/major defects before release. The permanent verification evidence remains under `docs/evidence/v1.1.2/`.

## Release-process governance

This release also closes the process failure that allowed implementation completion to be mistaken for release completion.

The canonical release authority remains `docs/releases/README.md`. Ordinary PRs now declare an explicit machine-checked handoff:

- `continue-development`; or
- `create-release-pr-after-merge`.

Release-status evaluations must walk the canonical publication sequence through release branch/PR, metadata transition, actual Release-workflow jobs, immutable tag, published GitHub Release and exact assets. Green workflow no-ops now state **NO RELEASE** and identify a pending release transition when one exists.

## Distribution

The corrected v1.1.2 distribution contract includes:

- `jig-linux-x64.tar.gz`;
- `jig-linux-arm64.tar.gz`;
- `jig-install.sh`;
- the original `SHA256SUMS`;
- production-signed `jig-android.apk`;
- `jig-android.apk.sha256` for the bounded post-publication Android completion.

The Android completion is built from the unchanged immutable `v1.1.2` release commit, uses the stable production Android signing identity and appends only the missing APK/checksum assets; it does not move the tag, replace the Linux assets or rewrite the original `SHA256SUMS`. F-Droid remains the intended Android application-repository channel, but external submission/publication is deferred and is not a v1.1.2 release gate.
