# Jig 1.1.1 — release notes

**Status:** Final release notes for Jig v1.1.1.  
**Target tag:** `v1.1.1`

Jig 1.1.1 is a patch release over v1.1.0. It does not change product/runtime behavior. The patch corrects the public installation documentation, verifies the documented two-phase installation against the actual published release channel, and hardens the release-merge contract that governs future publication.

## Two-phase installation

The normal user path is now documented exactly as implemented.

### Phase 1 — install Jig

```bash
curl -fsSL https://github.com/pontivus-com/jig/releases/latest/download/jig-install.sh \
  | bash
```

This installs the certified Jig runtime and starts bootstrap mode. A plain `curl` without `| bash` only prints the installer source.

### Phase 2 — choose the planning repository

```bash
jig
```

Jig opens the local setup flow. The user then either selects an existing writable Git worktree or connects the shared **Jig Desktop & Mobile** GitHub App and chooses an eligible repository.

The direct `--repo` and `--repo-url/--checkout` forms remain supported as explicit noninteractive automation modes; they are no longer presented as the normal Quick start.

## Public-channel installation evidence

The documented flow was exercised end to end against the actual public GitHub Release channel in hosted run `44915232912`.

The smoke test:

- downloaded `releases/latest/download/jig-install.sh`;
- executed the exact documented Phase 1 pipe-to-bash command;
- verified the installed launcher and pinned runtime;
- verified fresh bootstrap status with no configuration pre-created;
- started the installed Jig runtime using the documented foreground fallback required on hosted Actions;
- verified the installed `jig` launcher reached the real bootstrap UI;
- completed Phase 2 against a real temporary Git repository through the installed setup API;
- verified `~/.config/jig/config.json`, repository `.jig/local/jig.sqlite`, and configured `jig status`.

The one-off workflow used to produce this evidence was removed before the remediation PR merged.

The permanent source-level installer/lifecycle suite and the full hosted Verify suite also remained green, including Linux/browser, Android build certification and Android API-24 runtime.

## Release ceremony hardening

The canonical release documentation now states an invariant exposed during the v1.1.0 publication repair: the final release/finalization commit must have the pre-release `master` candidate as its first parent.

A normal GitHub merge commit or squash merge satisfies that contract. Directly fast-forwarding a multi-commit `release/vX.Y.Z` branch can leave `HEAD^` inside the metadata branch after the version transition and cause the permanent Release workflow to correctly treat the final tree as a no-op.

The governed same-version pre-tag finalization path remains available for recovery before an immutable tag exists.

## Distribution

The public GitHub Release remains Linux-only:

- `jig-linux-x64.tar.gz`;
- `jig-linux-arm64.tar.gz`;
- `jig-install.sh`;
- `SHA256SUMS`.

Android APKs are not GitHub Release assets.

F-Droid remains the first intended public Android distribution target, but external submission/publication remains deferred until Jig is considered stable and the required marketing/store material is ready.

## Runtime scope

There are no product/runtime changes relative to v1.1.0. The v1.1.0 implementation evidence remains the runtime authority for this patch.
