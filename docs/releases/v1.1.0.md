# Jig 1.1.0 — release notes

**Status:** Final release notes for Jig v1.1.0.  
**Target tag:** `v1.1.0`

Jig 1.1.0 is the first minor release to extend Jig beyond the Linux/Desktop-only operating model while preserving one canonical Task/planning model, one local-first persistence contract and one portable Git-backed data contract.

The release adds the independently installable Android application, real GitHub Device Flow onboarding, secure platform credential storage, native Android reminders, bounded recurrence, the rolling seven-day Planner horizon, and the completed v1.1 mobile/desktop interaction hierarchy.

## Rolling seven-day Planner

Planner now uses one forward-looking seven-day horizon rather than a fixed Monday–Sunday week.

- startup shows today plus six future dates;
- Previous/Next move by exactly seven civil days;
- Previous cannot move before today;
- Today returns directly to the current horizon;
- a current horizon advances at local midnight while an intentionally viewed future horizon remains selected;
- global Add owns today;
- date-level `+` creation exists only for future dates.

Adjacent-week Carousel/swipe paging is explicitly deferred beyond v1.1. Previous/Next/Today are the complete v1.1 horizon-navigation contract.

## Android application and continuity

Jig now includes the independently installable Android application `com.pontivus.jig`.

Android reuses the same canonical planning semantics and portable records as Linux/Desktop while providing platform effects for app-private SQLite, secure credential storage, Git transport, lifecycle integration, local reminder scheduling and native system-bar/back behavior.

The application remains local-first: canonical planning mutations commit locally first and Git synchronization proceeds independently.

## GitHub onboarding and repository access

Fresh setup provides one governed **Connect GitHub repository** intent through the shared **Jig Desktop & Mobile** GitHub App and direct Device Flow.

The implementation includes:

- visible/copyable GitHub user code;
- automatic Device Flow polling;
- complete installation/repository pagination;
- automatic access re-checks;
- managed repository acquisition;
- device-local credential storage;
- authorization-only reconnect without repository re-selection.

## Recurrence, Task movement and workspace

v1.1.0 adds bounded weekly/monthly recurrence with one canonical series owner. Automatic rollover prevents older overdue outstanding recurring siblings from accumulating beside the latest due occurrence while preserving completed, future and explicitly future-rescheduled occurrences.

The rejected Pangea movement path is replaced by the proof-gated dnd-kit owner with a dedicated drag grip, explicit insertion slots, exact same-date/cross-date movement and terminal drag-state cleanup.

Add/Edit use one complete Task form. Add focuses Title; Edit does not force Title autofocus. Successful mutations close the workspace and provide the governed `Task added`, `Task saved`, `Task completed` and `Task reopened` confirmations.

## Application hierarchy, status and motion

The configured mobile application now uses the governed Planner/History/Settings hierarchy with persistent bottom navigation, one Planner Add action and explicit temporal controls.

History and Settings use the application header as the single destination title/subtitle owner. Settings separates user-level planning continuity from subordinate technical diagnostics.

Operational error/warning presentation uses one shared Jig-owned attention composition. The cross-platform motion contract covers workspace transitions, navigation and Task/status feedback while respecting reduced-motion preferences and never owning canonical state.

## Distribution

The public GitHub Release for v1.1.0 remains Linux-only:

- `jig-linux-x64.tar.gz`;
- `jig-linux-arm64.tar.gz`;
- `jig-install.sh`;
- `SHA256SUMS`.

Android APKs are not GitHub Release assets.

F-Droid remains the first intended public Android distribution target, but external submission/publication is deliberately deferred until Jig is considered stable and the required marketing/store material is ready. v1.1.0 requires F-Droid-compatible source/build metadata and readiness validation only.

## Architecture preservation

The v1.1.0 implementation preserves:

- functional core / imperative shell;
- one canonical Task and TaskCommand model;
- one canonical planning implementation;
- SQLite as local operational authority;
- one portable Jig record contract;
- Git as repository/synchronization transport authority;
- one shared GitHub authorization/onboarding orchestration contract;
- strict TypeScript boundaries;
- no DTO/ViewModel hierarchy;
- no service/repository/use-case stack;
- no second mobile Task model or cloud Task store;
- public Astryx APIs/tokens only.
