# Jig 1.0.2 — release notes

**Status:** Final release notes for Jig v1.0.2.  
**Target tag:** `v1.0.2`

Jig 1.0.2 is a patch release focused on daily-planning correctness, reminder behavior, governed release discipline, and restoring the Jig UX/UI through the public Astryx 0.7.13 architecture.

## Daily rollover

Unfinished prior-day Tasks now use persisted daily rollover rather than a derived carry-over presentation.

That means overdue work is physically moved into the current local date and remains consistent across:

- Day and Week views;
- application restart;
- portable-data synchronization;
- subsequent Task commands.

Task command admission performs rollover before revision validation so clients holding a pre-rollover revision are rejected safely rather than mutating against stale planning state.

## Day and reminder behavior

Day is the default planning entry surface. The browser revalidates canonical state across local day boundaries so a long-running session does not retain yesterday's planning state.

Reminder delivery uses one eligibility path:

- visible application: in-app reminder toast;
- hidden/open application with browser permission: browser Notification.

Browser notification permission is requested only from the explicit Settings action, and browser/in-app delivery share the same duplicate-suppression state.

## UX/UI and Astryx architecture

The v1.0.2 UI has been re-certified against the governed desktop/mobile structural references.

The implementation keeps the intended ownership boundary:

- Astryx `AppShell`, navigation, dialog, form, list, Button and Link primitives own reusable mechanics;
- Jig CSS owns only Jig-specific product composition and governed structural geometry;
- ordinary spacing, type, radius, motion and color consume public Astryx semantic tokens;
- custom Jig theme authoring lives in `ui/src/jig-theme.source.ts`;
- pinned `@astryxdesign/cli@0.7.13` generates the committed runtime `jig.js` / `jig.css` artifacts;
- CI runs `astryx theme build --check` to reject stale generated theme artifacts;
- Jig-authored code does not depend on private Astryx selectors, variables, StyleX details or compiler markers.

Fresh real-browser evidence covers Week Light/Dark, Day, History, Settings, Mobile Day, Mobile editor, repository-sync failure and local-save failure states.

## Release governance correction

The release contract now makes the publication transition explicit:

- implementation PRs do not change `package.json.version`;
- every release requires a dedicated `release/vX.Y.Z` metadata PR;
- that PR must explicitly set `package.json.version` to `X.Y.Z`;
- package version, changelog section, release note and tag must agree;
- a green Release workflow that exits with `should_release=false` is a no-op, not a released version;
- a release is valid only after the exact release commit is certified, tagged and published with the complete x64/arm64/installer/checksum asset set.

## Release certification

The permanent release path re-runs the full verification set before publication, including:

- frozen dependency installation;
- release-metadata verification;
- Astryx theme artifact drift checks;
- TypeScript;
- core/integration tests;
- production UI build;
- real-browser acceptance;
- shell syntax;
- installer/lifecycle smoke;
- native arm64 certification;
- packaged x64 and arm64 bundle smoke tests;
- SHA-256 verification.

The published asset contract remains:

- `jig-linux-x64.tar.gz`;
- `jig-linux-arm64.tar.gz`;
- `SHA256SUMS`;
- `jig-install.sh`.

## Installation

After v1.0.2 publication:

```bash
curl -fsSL https://github.com/pontivus-com/jig/releases/latest/download/jig-install.sh \
  | bash -s -- --repo /absolute/path/to/your/planning-repo
```

See [installation](../install.md) for the supported repository-selection modes and lifecycle behavior.
