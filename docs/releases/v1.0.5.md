# Jig 1.0.5 — release notes

**Status:** Final release notes for Jig v1.0.5.  
**Target tag:** `v1.0.5`

Jig 1.0.5 is a corrective patch over v1.0.4. It fixes the interaction and responsive-presentation defects found after v1.0.4 publication without changing Jig's canonical Task, persistence, rollover, reminder, Git-synchronization, installer or release architecture.

## Crash-free whole-card movement

Drag-and-drop now keeps React and the canonical Task order as the only authoritative ordering state.

dnd-kit continues to own sensing, collision detection and the drag overlay, while optimistic DOM sorting is suppressed during drag. This removes the cross-list React reconciliation failure that could surface as a `removeChild` `NotFoundError`.

The entire non-interactive Task card is now the drag source. Checkbox, menus, reference actions and other interactive descendants remain independently usable.

The release preserves exact canonical movement semantics for:

- same-date reorder;
- cross-date movement into non-empty dates;
- cross-date movement into empty dates;
- reload persistence;
- non-drag Move up / Move down alternatives.

An activated drag does not also select the Task or open the workspace when released.

## Desktop and narrow/mobile parity

Planner now uses one responsive semantic path rather than separate desktop and narrow interaction owners.

Desktop and narrow/mobile share:

- one dated-section renderer;
- one sortable Task-list path;
- one Task row/action model;
- one Planner / History / Settings destination definition;
- one Task action-menu vocabulary;
- the same Task state and surface semantics.

Narrow/mobile supports direct touch drag with an intentional long-press activation threshold instead of treating Move up / Move down as a substitute for drag.

## Compact application chrome

The application header is reduced to a flat edge-to-edge bar with one bottom hairline:

- desktop height is at most 44px;
- narrow/mobile height is at most 56px;
- temporal controls remain on one line;
- the complete Jig wordmark is used instead of combining a standalone mark with duplicate live text.

Application-level viewport gutters and framed outer chrome are removed. The seven-track desktop Planner begins at the governed 73rem / 1168px breakpoint.

## Semantic icon and menu normalization

Visible actions, metadata and status affordances now use the Astryx semantic icon system consistently.

Jig owns only four namespaced extension meanings where the pinned Astryx registry does not provide the required semantic glyph:

- `jig:add`;
- `jig:history`;
- `jig:edit`;
- `jig:delete`.

Planner, History and Settings navigation use the same semantic destination definition across desktop and narrow/mobile. Task action menus use the same meaning, labels and icon treatment in both layouts.

## Task-card legibility

Task cards use one governed surface/border owner across Planner and History.

Light mode keeps White cards over the Paper canvas. Dark mode raises Task cards to Ink 800 over the Ink 950 canvas with the governed emphasized neutral border, preserving visible separation on both desktop and narrow/mobile.

Selection, focus, drag and priority states remain separate semantic layers rather than being encoded by the base Task surface.

## Architecture preservation

The correction does not introduce a second product model or responsive domain.

The implementation preserves:

- functional core / imperative shell separation;
- one canonical `Task` and `TaskCommand`;
- strict TypeScript typing;
- one canonical Task-order owner;
- no DTO/ViewModel hierarchy;
- no service/repository/workflow abstraction stack;
- Astryx public component/theme/icon ownership;
- generated theme artifacts from the canonical Jig theme source.
