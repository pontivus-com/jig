# Jig 1.0.3 — release notes

**Status:** Final release notes for Jig v1.0.3.  
**Target tag:** `v1.0.3`

Jig 1.0.3 is a patch release that completes the single-Planner interaction model and removes the remaining Day/Week navigation split without changing Jig's Task, persistence, rollover, reminder or Git-synchronization semantics.

## One Planner

Planner is now Jig's implicit Home and the only primary planning destination.

Desktop presents one seven-date weekly board. Narrow/mobile presents the same Planner state as a seven-date strip plus the selected date's outstanding Task list.

History and Settings are the only secondary destinations:

- desktop exposes them directly in the global application header;
- narrow/mobile exposes them through a compact anchored popover;
- the removed SideNav/mobile navigation drawer does not remain as a parallel navigation model.

## Centered week navigation

The active week range is page-centered as the temporal centerpiece.

Directly beneath it, one grouped control row provides:

- Previous week;
- Today;
- Next week.

Previous/Next move the displayed week and selected date by exactly seven civil days while preserving weekday. Today restores the current local date and its containing week. Selecting a visible date changes Planner selection only and does not mutate Task data.

## Task inspection, editing and movement

Task click/tap now means inspect only.

One canonical Task-workspace state drives both responsive presentations:

- desktop Planner and History use a non-modal right Astryx Drawer;
- narrow/mobile uses Astryx BottomSheet from the bottom;
- responsive reflow preserves the selected Task, workspace mode and unsaved draft.

Create initially asks only for title and inherits the selected/originating date. Edit exposes the full optional Task fields.

The separate Move-to-date workspace/action has been removed:

- desktop drag owns exact same-date reordering and cross-date movement;
- Move up/Move down remains the explicit non-drag same-day ordering alternative;
- Edit scheduled date owns explicit non-drag rescheduling.

Permanent Delete confirmation remains the only blocking Task dialog.

## Completion and History

Completed Tasks leave Planner immediately and remain inspectable/reopenable in History.

Reopen preserves Task identity and the existing canonical ordering rule: the Task returns at the end of its scheduled date's outstanding order.

Planner therefore remains an outstanding-work surface rather than maintaining a second completed section.

## Responsive and visual hierarchy

Desktop Planner consumes the available canvas with seven equal fluid date tracks and a governed 160px minimum per track.

The responsive switch is derived from that geometry at 76rem rather than the earlier Day/Week breakpoint.

Selected date, today, Task selection and drag target remain visually distinct. Task priority uses restrained theme-derived leading cues consistently across Planner, History and detail without becoming an ordering authority or relying on color alone.

System, Light and Dark retain the same interaction hierarchy.

## Preserved core behavior

1.0.3 does not redesign Jig's domain or integration boundaries.

The release preserves:

- the canonical Task model and stable identity;
- local civil scheduled dates;
- persisted outstanding position;
- priority-assisted insertion;
- exact-position move semantics;
- persisted daily rollover;
- completion/reopen/delete behavior;
- reminder semantics;
- SQLite durability and revision admission;
- deterministic portable records;
- automatic Git synchronization and coarse sync status;
- local-save versus synchronization-failure truth;
- installer and lifecycle behavior.

The only planning-core code change is extraction/reuse of the pure Monday week-start helper so Planner has one civil-week rule.
