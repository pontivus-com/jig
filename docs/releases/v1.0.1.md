# Jig 1.0.1 — release notes

**Status:** Release-candidate notes; final publication is gated by the v1.0.1 release workflow.  
**Target tag:** `v1.0.1`

Jig 1.0.1 is a corrective release that restores the intended separation of concerns around Git integration and fixes the installer failures exposed by ordinary developer Git configuration.

## Ownership-boundary correction

Jig continues to own:
- canonical Task/planning behavior;
- local SQLite durability;
- deterministic portable Jig records;
- automatic background synchronization;
- coarse synchronization status;
- adoption of valid existing Jig data from the selected repository.

Git remains authoritative for:
- repository organization and topology;
- branch/ref/worktree mechanics;
- user identity and signing policy;
- credentials and authentication;
- history and reconciliation.

Git mechanics required by synchronization are now confined to the repository adapter rather than application configuration, UI, CLI workflow or installer semantics.

## Installer fixes

The supported installer still accepts both target forms:

```bash
jig-install.sh --repo /absolute/path/to/existing/repository
```

and:

```bash
jig-install.sh \
  --repo-url git@github.com:you/planning.git \
  --checkout /absolute/new/path/planning
```

URL mode delegates acquisition to Git and then enters the same selected-checkout installation path.

1.0.1 fixes the two v1.0.0 installation failure classes:

- Jig-generated synchronization commits no longer inherit the user's commit-signing requirement. The override is scoped to the individual Jig machine commit and does not modify user or repository Git configuration.
- Fresh initialization no longer publishes an empty invalid Jig bootstrap ref before a valid portable snapshot exists. The first observable Jig data commit is already a valid empty portable snapshot.

The installer also narrowly recognizes and repairs the exact empty bootstrap residue produced by the v1.0.0 failure. Unknown malformed Jig data remains non-destructive and is not treated as a general Git-repair problem.

## Removed scope creep

1.0.1 removes the application-level repository migration subsystem:

- no `jig configure --repo`;
- no repository-migration HTTP endpoint;
- no migration Settings workflow;
- no migration-specific writer/restart orchestration.

Repository continuity is Git-native: obtain or clone the desired checkout and install Jig against it. If valid Jig portable data already exists there, Jig adopts it automatically.

Application configuration is reduced to Jig-owned runtime state:

```json
{
  "version": 1,
  "repository_path": "/absolute/path/to/repository",
  "http_port": 47831
}
```

Git remote/ref/worktree state is no longer persisted as Jig application configuration.

The v1.0.0 SQLite `app_metadata.data_ref` field is removed as well. Existing databases migrate in place from schema v1 to v2 while preserving Tasks, dataset identity, revisions and synchronization bookkeeping.

## Synchronization behavior

Automatic synchronization remains required and unchanged at the product level:

- successful Task edits commit locally without waiting for Git;
- background synchronization continues while the service is running;
- transient synchronization failure retries automatically;
- Git failure never rolls back a successful local Task save;
- unrelated repository content is never staged or committed by Jig;
- the UI exposes only coarse operational outcomes such as local-only, pending/retrying, synchronized and sync-issue.

Remote choice follows Git/user configuration rather than a Jig-specific remote setting. Jig does not change Git signing, identity, credential or repository policy.

## Certification additions

The v1.0.1 verification set adds coverage for:

- existing-checkout installation;
- repository-URL installation;
- repositories with unrelated user content;
- commit signing enabled without a Jig key;
- SSH signing configuration;
- unavailable repository transport;
- installer rerun/idempotency;
- exact v1.0.0 empty-bootstrap recovery;
- adoption of existing Jig portable data without an existing local SQLite database;
- unknown malformed Jig data remaining non-destructive;
- Linux x64 and arm64 packaged release certification during the permanent release workflow.

## Installation

Latest stable after v1.0.1 publication:

```bash
curl -fsSL https://github.com/pontivus-com/jig/releases/latest/download/jig-install.sh \
  | bash -s -- --repo /absolute/path/to/your/planning-repo
```

See [installation](../install.md) for both supported repository-selection modes.
