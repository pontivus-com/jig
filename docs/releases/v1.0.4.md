# Jig 1.0.4 — release notes

**Status:** Final release notes for Jig v1.0.4.  
**Target tag:** `v1.0.4`

Jig 1.0.4 is a corrective patch over v1.0.3 that completes the intended single-Planner interaction model without changing Jig's canonical Task, persistence, rollover, reminder, Git-synchronization, installer or release architecture.

## One displayed-week Planner

Planner now has one writable time state: the displayed Monday-starting week.

There is no selected-day state, DateStrip or selected-date subview. Desktop presents seven equal dated tracks, while narrow/mobile presents the same seven dates as stacked sections.

Each section uses the full weekday/date label and its own compact Add action. Global Add derives the current weekday position inside the displayed week rather than storing another date-selection state.

## Direct Task editing

Selecting a Task opens the complete editable Task workspace immediately.

Existing Tasks and new Tasks use the same field hierarchy:

- Title;
- Date;
- Context;
- Priority;
- Reminder;
- Reference;
- Notes.

Desktop renders the workspace through the non-modal right Drawer and narrow/mobile through BottomSheet. Responsive reflow preserves the same unsaved draft.

Blank Planner/History content dismisses the workspace without saving, while Task-to-Task selection retargets directly.

## Movement and Task actions

Card-body drag-and-drop is restored as the direct manipulation path while checkbox, menu and reference controls remain independently usable.

The release preserves Jig's existing exact move semantics for:

- same-date reorder;
- cross-date movement;
- empty-date destinations;
- Move up / Move down as the non-drag ordering alternative.

Planner and History Task menus now expose the complete relevant direct actions, including priority changes, completion/reopen, movement where applicable and confirmed permanent deletion. Priority edits do not reorder an established manual sequence.

## Visual hierarchy and status semantics

The weekly Planner is an open reduced-chrome canvas rather than seven framed panels. Date tracks use whitespace and restrained separation; Task cards remain the primary discrete interaction surfaces.

Desktop keeps explicit Planner, History and Settings navigation in the right side of the stable application header while temporal controls remain centered.

Light and Dark modes use distinct governed semantic roles for:

- current local date;
- selected/open Task;
- drag and keyboard focus;
- High, Normal and Low priority;
- Local only and Synced;
- pending/retrying;
- synchronization/save failure;
- unknown operational state.

`Local only` remains explicitly labeled and is represented as healthy local durability, not as an ambiguous unknown state.

## Architecture correction

v1.0.4 closes the interaction correction without introducing parallel product machinery.

The implementation preserves:

- the functional core / imperative shell boundary;
- one canonical Task and TaskCommand;
- strict TypeScript typing;
- one displayed-week Planner owner;
- one discriminated Task workspace owner;
- shared desktop/narrow Task-sequence semantics;
- runtime narrowing at repository, SQLite and HTTP boundaries;
- Astryx as the reusable component/theme/icon authority.

The obsolete DateStrip and read-only Task inspector are removed rather than retained as dormant alternate owners.

## Preserved core behavior

The release does not redesign Jig's domain or integration boundaries. It preserves:

- canonical Task identity and schema;
- local SQLite durability and revision admission;
- priority-assisted initial insertion;
- exact-position move semantics;
- persisted daily rollover;
- completion, reopen and delete semantics;
- reminders;
- deterministic portable records;
- automatic Git synchronization and coarse synchronization outcomes;
- installer/lifecycle behavior;
- the governed immutable release process.
