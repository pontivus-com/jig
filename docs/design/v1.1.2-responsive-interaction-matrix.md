**Status:** BINDING v1.1.2 UI ownership matrix.

The implementation topology is governed by [v1.1.2 responsive presentation architecture](../architecture/v1.1.2-responsive-presentation-architecture.md). Material composition differences use separate desktop/narrow presenters; shared semantic leaves remain singular.

## Rules

1. Responsive differences are **presentation ownership**, not duplicate Task/Planner/synchronization state.
2. A mobile-specific fixed/floating surface may not render on desktop.
3. A desktop-only dense composition may not be reused on touch if it violates >=48px interaction geometry or safe areas.
4. One semantic action may have two viewport-specific presentations only when the matrix declares that split.
5. Astryx adaptive primitives remain preferred when their public API produces correct desktop and narrow behavior; Jig creates a split only when the primitive or composition requirement materially differs.
6. Every matrix row must receive desktop + narrow/mobile real-browser acceptance before v1.1.2 release.
