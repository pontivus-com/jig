# Jig v1.1.2 adaptive presentation and platform concern matrix

**Status:** BINDING v1.1.2 ownership and acceptance registry.  
**Tracking issue:** #66.

This registry separates three concerns that must not be conflated:

- **presentation class:** desktop/expanded versus narrow, selected only by the 73rem width boundary;
- **runtime capability:** Linux/browser versus Android/native;
- **input/capability fact:** touch/coarse pointer, mouse/pen, keyboard and IME behavior observed only where needed.

The detailed architecture is governed by [v1.1.2 adaptive presentation and runtime architecture](../architecture/v1.1.2-responsive-presentation-architecture.md).

## D. Architecture rules

1. `LayoutMode` selects presentation only.
2. Raw native/platform detection selects platform mechanics only.
3. Pointer/IME facts are observed where needed and do not become domain/application state.
4. Feature presentation must not call `Capacitor.isNativePlatform()` directly.
5. Runtime/Git/persistence adapters must not use `LayoutMode`.
6. Only one desktop or narrow presentation tree is mounted.
7. Shared semantic state remains above both presentation and platform mechanics.
8. Platform-specific actions are rendered from actual capability state, not inferred from width.
9. Existing-local-repository onboarding is controlled by setup capability, not by desktop layout.
10. Android exact-alarm UI is controlled by notification capability, never shown in browser mode.
11. Native Back/activation/system bars have one bounded owner each.
12. Safe-area inset has one owner per application edge.
13. New v1.1.2 concerns must be added to this registry before implementation.
14. Every row must have automated architecture/browser evidence where feasible and physical Android evidence for native-only interaction that cannot be proven in Chromium.

## E. Required acceptance combinations

At minimum:

| Combination | Required evidence |
|---|---|
| Expanded Linux/browser + fine pointer | header/nav/Add/status, seven-track Planner, Drawer, desktop feedback, Settings/Diagnostics, browser notification capability |
| Narrow Linux/browser + fine pointer | narrow header/bottom nav/FAB, stacked Planner, BottomSheet, narrow feedback, **browser** capabilities remain browser |
| Narrow browser + coarse-pointer emulation | touch geometry, touch drag activation, no Android-only capability leakage |
| Android/native narrow | native Back, activation/resume, safe areas/system bars, GitHub continuation, app-private setup, Android notification/exact-alarm UX, touch/IME |
| Android/native expanded, if supported by current runtime/window configuration | expanded presentation + native capabilities + touch/coarse-pointer accessibility |

The release candidate fails this registry if one of these combinations produces the correct layout but the wrong platform capability, or the correct platform capability but the wrong presentation.
