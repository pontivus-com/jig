# Jig product identity

**Status:** Canonical v1 public product identity baseline.  
**Scope:** Naming, public descriptor, release-facing message hierarchy and visual identity.  
**Non-scope:** Task semantics, runtime architecture, persistence, repository synchronization or interaction behavior.

## Message hierarchy

### Primary

> **Plan the day. Stay on track.**

### Supporting

> **Jig schedules attention, not project execution.**

### Standard description

> Jig is a local-first just-in-time daily planner. Put lightweight intentions on dates, order them explicitly, carry unfinished work forward visibly, and reorganize the day without turning personal planning into another project-management workflow.

## Visual identity

The canonical visual metaphor is **guide / alignment**.

A physical jig briefly guides something into the right position without becoming the work itself. Jig does the same for attention: it helps place the next intention in the day while the underlying project work remains in its authoritative system.

The canonical mark is a geometric **J-shaped guide with one highlighted alignment pin**. The letterform makes the mark product-specific; the pin represents the lightweight intention being guided into position.

### Colour

- Ink: `#14202B`
- Dark surface: `#101820`
- Jig amber: `#F5A623`
- Warm highlight: `#FFD166`
- White: `#FFFFFF`

The symbol must also work in one colour.

### Do not

Do not turn the mark into:

- a checkmark;
- a calendar-page illustration;
- a clock;
- a Kanban board;
- a robot/AI sparkle;
- Git branches or commit nodes;
- a literal woodworking jig or clamp.

The brand communicates lightweight guidance and attention, not workflow completion or project execution.

## Family relationship

Jig is a separate Pontivus tool alongside Span and Order.

- **Span** preserves engineering understanding.
- **Order** carries software work to verified results.
- **Jig** schedules personal attention across the day.

The products may reference one another, but Jig remains deliberately independent of Order's lifecycle and Span's knowledge model.
