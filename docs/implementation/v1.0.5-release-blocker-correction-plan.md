## 1. Problem statement

Direct validation after v1.0.4 publication exposed failures that the v1.0.4 verification set did not detect:

1. cross-list card drag can crash React reconciliation with `NotFoundError: Failed to execute 'removeChild' on 'Node'`;
2. narrow/mobile deliberately disables direct drag;
3. Planner rendering branches into sortable desktop versus non-sortable narrow code paths;
4. desktop and narrow navigation use different hard-coded destination sets; the narrow menu omits Planner;
5. responsive Task action parity was not explicitly certified;
6. required semantic iconography is incomplete and raw Unicode stand-ins remain;
7. the application header is materially too tall;
8. Task cards lack sufficient canvas separation, especially on narrow/Dark where container and card use the same surface;
9. header brand composition violates the canonical complete-wordmark contract;
10. architecture/browser gates certified component presence without proving responsive semantic parity;
11. the application frame carries unnecessary desktop/narrow viewport insets and framed content chrome instead of the required zero-margin full-bleed composition.

This patch fixes those defects without changing Task/domain/persistence/Git semantics.

## 2. Non-negotiable architecture constraints

Every task below must preserve these invariants as it lands:

- **FCIS:** `src/core/**` stays pure; browser presentation/I/O stays in `ui/src/**`; shell integration stays in `src/shell/**`.
- **One canonical Task/order owner:** do not create a client-side Task-order mirror, drag DTO, mobile Task projection or parallel canonical sequence.
- **Responsive SoC:** layout mode may select presentation primitives whose anatomy genuinely differs (Drawer vs BottomSheet, desktop header vs narrow header), but must not toggle Task capabilities, menu semantics, destination semantics, ordering semantics or color semantics.
- **DRY:** one dated-section renderer, one sortable Task row path, one destination definition, one Task action-menu owner, one Task-surface token mapping and one icon vocabulary.
- **Strict typing:** no new `any`, `unknown as X`, double casts, non-null assertions or unchecked product/domain assertions. Use public Astryx/dnd-kit exported types and guards. Localized third-party ref assertions may remain only where the library type cannot represent the verified element subtype.
- **No DTO/mapping hierarchy:** UI semantic constants/functions are not transport/domain DTOs. Do not add service/repository classes, command buses, workflow/state frameworks or mapping stacks.
- **Astryx authority:** use public Astryx primitives/tokens/icon seams. No private selectors/custom properties, no `!important`, no second icon/UI library.
- **No release pollution:** do not change `package.json.version`, create `docs/releases/v1.0.5.md`, or move v1.0.4 release metadata on this implementation branch.

### J105-IMP-01 — Make drag crash-free by restoring one DOM/order owner

**Closes:** JIG-105-FR-01 / JIG-105-SD-01 only.

**Primary files**
- `ui/src/drag.tsx`
- `tests/browser/interactions.spec.ts`
- `tests/browser/ui-conformance.spec.ts`

**Required implementation**
1. Add `onDragOver` to the existing `DragDropProvider` and call `event.preventDefault()` unconditionally for Jig Task sorting. This suppresses dnd-kit's default optimistic DOM reordering so React/canonical state remains the rendered-order owner.
2. Keep `activeTaskId` as transient overlay state only.
3. Preserve one `onDragEnd` command submission:
   - narrow source/target with dnd-kit's public `isSortable` guard;
   - sortable target => `group` + exact `index`;
   - date droppable => its explicit `data.date` and canonical outstanding count excluding source;
   - cancelled/null/no-op => no command.
4. Do not mutate the canonical Task array or maintain temporary client sequence arrays during drag.
5. Do not send move commands from `onDragOver`.

**Verification**
- browser fixture installs `page.on("pageerror")` and console-error collection before drag;
- same-date and cross-date desktop drag complete with zero collected runtime errors;
- canonical API order/date is exact after drop and after reload;
- cancelled drag produces no canonical mutation.

**Done when**
FR-01 browser acceptance passes and the drag module still has one provider/one canonical `onMove` path.

This deliberately permits Astryx's accessible row-selection overlay to initiate whole-card drag without coupling to Astryx private DOM. **Verification**

- touch cross-date move;
- touch drop into empty date;

### J105-IMP-06 — Complete one Astryx semantic icon vocabulary

**Closes:** JIG-105-FR-06 / JIG-105-SD-06 only.

   - Planner: viewColumns;

   - Settings: wrench;
   - hamburger: menu;
   - overflow: moreHorizontal;
   - reminder: clock;
   - web reference: externalLink;
   - copy reference: copy;
   - completion/current marker: check;
   - Move up/down: arrowUp/arrowDown;
   - status: success/warning/error/info.
2. Astryx 0.7.13 lacks true semantic Add, History, Edit and Delete names. Implement exactly four namespaced extensions using the Astryx-documented pattern: `jig:add`, `jig:history`, `jig:edit`, `jig:delete`.
   - one small `jig-icons.tsx` module;
   - `JIG_ICON_KEYS` declared `as const` and checked with `satisfies` against Astryx `NamespacedIconName` so extension keys cannot drift or require casts;
   - one `JigIconName = keyof typeof JIG_ICON_KEYS` union and an exhaustive fallback-glyph map keyed by that union;
   - bundled inline 24×24 fallback components;
   - `getExtendedIcon` + `Icon` using public `IconName`/`NamespacedIconName` types;
   - no `as IconName`, no `any`, no double cast and no new icon dependency.
3. Replace raw `+` in global/narrow/date Add controls with `jig:add`; use `jig:history` in navigation and `jig:edit`/`jig:delete` in Task menus. Use built-in arrows/check/status/reference icons for meanings already covered.
4. Do not add a second icon registry or wrapper hierarchy; one tiny extension renderer for the four missing meanings is sufficient.
5. Preserve accessible labels/text; icons are not the accessible name.

**Verification**
- static guard forbids governed raw stand-ins `+`, `•••`, `≡` in the relevant control components;
- browser checks required controls contain rendered SVG/icon content;
- navigation/task/status labels remain accessible.

**Done when**
