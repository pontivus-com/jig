# Jig v1.0.4 — interaction correction implementation plan

**Status:** Binding implementation plan for the v1.0.4 corrective patch.  
**Baseline:** published v1.0.3 on `master`; implementation branch `fix/v1.0.4-ui-interaction-corrections`.  
**Governing design:** JIG-104-FR-01…14 in the functional design, technical solution v0.10, UI solution v0.8.  
**Release rule:** this implementation branch keeps `package.json.version = 1.0.3` and accumulates notes under `[Unreleased]`. Version 1.0.4 is finalized only after implementation merges to `master` through a dedicated `release/v1.0.4` branch.

## Scope

This patch corrects user-visible interaction defects introduced or exposed by the v1.0.3 composition. It does not change Task schema, SQLite, HTTP contracts, Git synchronization, rollover, reminders, installer behavior or release tooling.

## Tasks

### J104-IMP-01 — Repair card-body pointer drag
- make the non-interactive Task body/title/meta region the dnd-kit sortable activation handle;
- keep checkbox, action menu and reference controls outside the drag activation region;
- preserve the existing exact-position `move` command and one dnd-kit owner;
- add real-pointer same-date and cross-date browser coverage using the card body rather than a tiny dedicated handle.

### J104-IMP-02 — Implement the governed component/state color contract
- perform a palette-completeness audit against brand/theme §6.1.1 before styling changes;
- do not proceed by reusing a semantically incorrect existing role merely to avoid extending the theme;
- if implementation discovers a governed state without a suitable accessible family, update the canonical theme contract and authored theme source first, then regenerate artifacts;
- add the exact Jig product-state semantic aliases from `brand-and-theme.md §6.2` to `jig-theme.source.ts`;
- regenerate `jig.js`, `jig.css` and declarations through the pinned Astryx CLI; never hand-edit generated theme artifacts;
- implement the component/state matrix in §6.3 exactly;
- delete desktop selected-day styles and any `--color-accent(-muted)` use whose only meaning is persistent Task/date/navigation selection;
- exact today uses `--jig-state-today-border/text`;
- selected Task uses `--jig-state-task-selected-bg/border`;
- active History/Settings uses `--jig-state-nav-active-bg/text`;
- drag source/drop target uses `--jig-state-drag-border/bg`;
- priority uses High=`--jig-priority-high`, Normal=`--jig-priority-normal`, Low=`--jig-priority-low`;
- Local only and Synced use the healthy status aliases; pending/retrying/error/unknown remain separately mapped as governed;
- primary/secondary/ghost/destructive buttons remain public Astryx variants and are not recolored per screen;
- hover and pressed states for Jig-owned surfaces use the neutral hover/pressed aliases; keyboard focus always uses the Amber focus role in addition to, never instead of, persistent state;
- verify Light and Dark resolved values against §6.4;
- add browser/computed-style assertions that today, selected Task, Normal priority, drag target, active navigation and Local-only do not collapse to the same background/border/text treatment.

### J104-IMP-03 — Collapse workspace into one editable surface
- change workspace state to `closed | task(taskId,draft) | create(originatingDate,draft)`;
- selecting an existing Task opens its full editable draft immediately;
- Add opens the same full form with inherited date/defaults;
- delete the read-only TaskInspector path from active composition;
- remove the second-click Edit indirection and v1.0.3 title-only create branch;
- Save uses the existing create/edit commands; Cancel closes without persistence.

### J104-IMP-04 — Outside-click dismissal
- Planner/History content pointer-down outside Task rows closes an open workspace without saving;
- Task-row clicks retarget directly to the clicked Task;
- workspace portal interaction, action menus, AlertDialog and reference controls must not be mistaken for outside clicks;
- explicit close/Escape behavior remains.

### J104-IMP-05 — Stable header height
- make the outer desktop header height invariant across Planner/History/Settings;
- reserve the same center-region vertical budget for temporal controls and destination titles;
- apply a stable narrow-header budget as well so navigation does not jump vertically;
- use public Astryx tokens/roles and governed Jig composition only.

### J104-IMP-06 — Complete Task action menus
Outstanding Planner menu:
- Open/Edit;
- Complete;
- Set priority High/Normal/Low with current value indicated;
- applicable Move up/Move down;
- Delete….

History menu:
- Open/Edit;
- Reopen;
- Set priority High/Normal/Low;
- Delete….

Priority menu actions issue the existing canonical edit command with only `priority`; established order must not change. Delete continues through AlertDialog.

### J104-IMP-07 — Browser/architecture regression gates
Cover:
- card-body drag same-date/cross-date exact position;
- future/past same weekday is not today;
- current day, selected Task, priority and drop target expose separate classes/computed styles;
- outside click closes workspace;
- another card retargets workspace;
- Add and existing Task show the same full field set;
- no separate Edit click is needed after selecting a Task;
- header bounding height is equal across Planner/History/Settings;
- menu Complete/Reopen/priority/Delete actions use canonical commands;
- responsive Drawer↔BottomSheet preserves unified draft.

### J104-IMP-08 — Date-header Add and content-driven lanes
- remove the full-width per-column Add task control from the bottom of desktop lanes;
- add one compact accessible `+` action beside each date/day number in the desktop column header;
- the header `+` opens the unified create draft for that explicit date without creating any selected-day state;
- preserve the global header Add task as a week-context shortcut using the derived weekday-matching date;
- remove footer-action CSS and any equal-height/stretch rules used only to pin that control;
- allow lane height to follow Task content while preserving equal widths and a minimum usable empty drop-target body;
- add browser coverage for date-header Add origin and variable-height drag/drop.

### J104-IMP-09 — Remove selected-day state
- reduce PlannerState to `displayedWeekStart` only;
- delete `selectedDate`, `selectDate`, date-label click selection, `DateStrip`, selected-date heading/list logic and all selected-day CSS;
- Previous/Next mutate only displayedWeekStart; Today restores the current week;
- derive global Add's default date as the current local weekday inside the displayed week;
- per-date `+` uses its explicit date directly;
- narrow/mobile renders all seven day sections vertically rather than one selected-date list;
- at local midnight, follow the new current week only when the user was viewing the prior current week; otherwise preserve the viewed week;
- add browser/state tests proving no same-weekday selection survives across weeks because no day-selection state exists.

### J104-IMP-10 — Operational-status semantics
- render `Local only` with the restrained success-family cue while retaining the explicit label;
- retain `Synced` as the distinct repository-synchronized success state;
- keep pending/retrying warning, sync issue error and unknown neutral;
- add browser/CSS assertions so Local only cannot regress to the unknown-grey treatment.

### J104-IMP-11 — Documentation/evidence/release preparation
- update AGENTS.md to the v1.0.4 workspace/menu/state rules;
- update v1.0.4 implementation evidence after browser certification;
- leave package version unchanged on the implementation branch;
- after merge to master, create `release/v1.0.4` and perform the normal governed metadata-only release transition.

## Definition of done

The patch is complete only when all JIG-104-FR-01…14 behaviors are implemented, the permanent verification suite is green, reviewed browser evidence demonstrates the corrected visual-state hierarchy, and no v1.0.3 release artifact/tag is rewritten.
