# Jig v1.0.4 — interaction correction implementation plan

**Status:** Binding, implementation-ready v1.0.4 corrective plan.  
**Baseline:** published v1.0.3 on `master`; implementation branch `fix/v1.0.4-ui-interaction-corrections`.  
**Governing functional design:** `JIG-104-FR-01…16` in `docs/requirements/planning-workbench.md` v0.9.  
**Governing technical design:** `docs/architecture/technical-solution.md` v0.11.  
**Governing UI/theme design:** `docs/design/ui-solution.md` v0.9 and `docs/design/brand-and-theme.md`.  
**Release rule:** this implementation branch keeps `package.json.version = 1.0.3` and accumulates notes under `CHANGELOG.md [Unreleased]`. Version 1.0.4 is finalized only after this implementation lands on `master`, through a dedicated `release/v1.0.4` branch.

## 1. Required outcome

v1.0.4 is a corrective UI/interaction patch over the published v1.0.3 single-Planner architecture.

The final product must have:

- reliable card-body drag-and-drop;
- no selected-day state or day selector;
- one displayed-week Planner state;
- full weekday labels (`Monday`…`Sunday`);
- per-date `+` in each date header and no bottom-of-lane Add action;
- content-driven desktop lane heights;
- global Add using a derived date inside the displayed week;
- one directly editable Task workspace for both existing and new Tasks;
- outside-click workspace dismissal;
- complete Task action menus;
- invariant application-header height across Planner/History/Settings;
- a complete, non-colliding Light/Dark semantic color system;
- `Local only` represented as healthy local durability rather than unknown grey;
- narrow/mobile as the same seven-day week expressed as stacked dated sections.

## 2. Preservation boundary

This patch is **not** a Task/domain/integration redesign.

Do not change:

- canonical Task identity or schema;
- SQLite schema or persistence ownership;
- HTTP command shapes;
- create/edit/move/complete/reopen/delete domain semantics;
- priority-assisted initial insertion;
- explicit exact-position move semantics;
- daily rollover;
- reminders;
- Git synchronization architecture;
- installer/lifecycle behavior;
- release workflow/tooling;
- pinned Astryx or dnd-kit versions.

Do not introduce:

- DTOs or mapping hierarchies;
- new service/repository layers;
- a second Task/order representation;
- another drag library;
- a second theme system;
- screen-local raw colors;
- a global state framework;
- selected-day state under another name;
- a second create/edit form.

## 3. Final presentation/state model

### 3.1 Planner

```ts
type PlannerState = {
  displayedWeekStart: LocalCivilDate; // Monday
};
```

Pure operations:

- Previous: `displayedWeekStart - 7 days`;
- Next: `displayedWeekStart + 7 days`;
- Today: Monday containing `currentLocalDate`;
- no `selectedDate`;
- no `selectDate()`.

Global Add derives, but does not store, a date:

```ts
defaultAddDate =
  addCivilDays(
    displayedWeekStart,
    weekdayOffsetFromMonday(currentLocalDate),
  );
```

Per-date `+` uses that section's explicit date directly.

### 3.2 Task workspace

```ts
type TaskWorkspaceState =
  | { mode: "closed" }
  | { mode: "task"; taskId: string; draft: TaskDraft }
  | { mode: "create"; originatingDate: LocalCivilDate; draft: TaskDraft };
```

There is no `view`, `edit`, or `move` submode.

Existing Task selection constructs an editable draft immediately. Create uses the same complete field hierarchy.

### 3.3 Responsive composition

Desktop:
- seven equal-width Planner tracks;
- minimum 160px per track;
- content-driven independent track heights;
- right Drawer overlays without reducing board width.

Narrow/mobile:
- the same displayed week;
- seven vertically stacked dated sections;
- no date strip;
- no selected-date heading/list;
- BottomSheet renders the same Task draft state.

## 4. Canonical color contract

Implementation must consume `docs/design/brand-and-theme.md §§6.1.1–6.4`.

Required semantic separation:

| Meaning | Canonical family |
|---|---|
| Today/current local date | teal |
| Selected/open Task | info blue |
| Drag/direct manipulation | Amber |
| Keyboard focus | Amber ring |
| High priority / destructive / errors | red/error |
| Normal priority / neutral structure/navigation | Ink/gray |
| Low priority / Local only / Synced | green/success |
| Pending/retrying | yellow/warning |
| Unknown operational state | neutral gray |

Implementation must add/use the governed Jig aliases in the authored theme source and regenerate the compiler-owned theme artifacts.

Do not use generic `--color-accent` / `--color-accent-muted` as a replacement for persistent Task selection, today, navigation, priority or operational-status semantics.
