## 3. Non-negotiable architecture constraints

Every task below must preserve all of these constraints.

1. Functional-core / imperative-shell dependency direction remains intact.
2. No DTO/view-model/service/repository hierarchy is introduced for presentation or platform separation.
3. No any, double casts, non-null assertions or unchecked cross-layer assertions are introduced.
4. Canonical Task/planning/workspace/navigation/synchronization semantics remain singular.
5. LayoutMode selects presentation only.
6. Raw native/platform detection selects platform mechanics only.
7. Pointer/keyboard/IME facts are observed only at the interaction/presentation boundary that needs them.
8. No global isMobile/device-class state is introduced.
9. Desktop and narrow presentation trees are never both mounted and CSS-hidden.
10. AppShell main is the sole configured application/page scroll owner.
11. Feature CSS consumes semantic/theme tokens only; no per-theme feature selectors or palette literals.
12. dnd-kit optimistic DOM sorting remains disabled.
13. Drag-over never mutates canonical Task state.
14. Git/platform work does not leak into Task/domain state.
15. Jig never force-pushes jig-data and never mutates unrelated repository history.
16. Normal synchronization root-cause correction is evidence-driven; automatic divergence recovery is a separate capability.
17. User-assisted conflict resolution is allowed only for the SD-16 eligible same-dataset semantic-conflict case; no arbitrary Git terminal/shell, raw conflict-marker editor or unrelated-history workflow is introduced.
18. Package version remains 1.1.1 throughout implementation. Version transition belongs only to the governed release/v1.1.2 ceremony.

#### A. Shared policy and exact merge

1. Recovery is considered only for `lineage=diverged` with exact local/remote heads, matching dataset identity and **exactly one** merge base. Zero or multiple merge bases => `ancestry-unknown`.
2. Validate ancestor/local/remote snapshots independently before merge.
3. Merge Tasks by Task id and recurrences by recurrence-series id using the exact canonical-record rule from SD-06:
   - L==R => take it;
   - L==A => take R;
   - R==A => take L;
   - absent in A + present on one side => take addition;
   - absent in A + identical on both sides => take addition;
   - present in A + deleted on one side + unchanged on the other => delete;
   - every other case => `semantic-conflict`.
4. Equality includes every canonical field, including timestamps, position and recurrence links. No field merge and no last-writer-wins logic is permitted.
5. Serialize the selected records through current `serializeSnapshot`, then validate with `validateSnapshot`, `assertTaskSet` and `assertRecurrenceState`. Combined-state invariant failure => `semantic-conflict`.
6. No force push.

#### B. Deterministic isolated candidate

7. Private recovery ref is exactly `refs/jig/recovery/<dataset-id>`.
8. Candidate tree contains only canonical portable files at mode 100644.
9. Candidate parents are the two pre-recovery heads sorted lexicographically by full object id.
10. Author/committer are exactly `Jig <jig@local.invalid>`.
11. Author/committer timestamp is exactly one second after the greater committer timestamp of the two parents, offset +0000.
12. Commit message is exactly `Reconcile Jig data`.
13. Linux constructs this object only through `src/shell/git/recovery.ts`; Android uses its isomorphic-git effect path. Neither moves authoritative `refs/heads/jig-data` during construction, and both write only the private recovery ref. Same heads + same merged snapshot must yield the same candidate object id.

#### C. Acceptance transaction

14. Re-check SQLite revision == expected revision and local jig-data head == expected local head.
15. Call revision-guarded `adoptCanonicalSnapshot(..., candidateHead, expectedRevision)`; this sets `last_adopted_head=candidateHead` and leaves `pending_sync=1`.
16. Advance local jig-data from expected local head to candidate:
    - Linux: `git update-ref refs/heads/jig-data <candidate> <expected-local>`;
    - Android: under the one in-process sync writer, resolve current app-private jig-data head, require exact expected-local equality, then write candidate; mismatch => `ref-race` and re-observe.
17. Run `markExported` only after SQLite canonical state and local ref both represent candidate.
18. Delete private recovery ref only after `markExported` succeeds.
19. Push with ordinary non-force semantics, re-observe, and mark synchronized only when remote exposes candidate.

#### D. Restart/interruption recovery

20. Private recovery ref exists but `last_adopted_head != candidate` => delete private ref and re-observe; no candidate was accepted.
21. `last_adopted_head == candidate`, canonical SQLite serializes byte-identically to candidate, and local head is one candidate parent => advance local head to candidate, mark exported, delete private ref, continue.
22. Same facts with local head already candidate => mark exported, delete private ref, continue.
23. Any proof mismatch => do not mutate refs/SQLite; enter attention with diagnostics.
24. No synchronization table or new metadata column is permitted in v1.1.2.

#### E. Android parity

25. Android isomorphic-git implements the same merge, deterministic-object, private-ref, acceptance and restart contract. The pure three-way record decision function is shared; native code does not duplicate it.

#### F. Guided conflict case

26. When automatic recovery reaches semantic-conflict, expose a conflict case **only** when SD-16 eligibility is satisfied: exact heads, exactly one merge base, matching dataset, three valid snapshots and the expected SQLite revision.
27. Implement the shared pure conflict extractor exactly as SD-16:

    - any connected component with at least one recurrence-series id and at least one conflicting Task/series record is one recurrence-family conflict;
    - include every series and Task in that connected component on each side;
    - only conflicts whose component has no recurrence-series id remain standalone Task conflicts;
    - non-conflicting records retain the automatic SD-06 merge result.
28. Add exactly the two configured-runtime operations from SD-16:
    - readSynchronizationConflict;
    - resolveSynchronizationConflict.
