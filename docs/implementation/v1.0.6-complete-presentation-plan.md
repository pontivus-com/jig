# Jig v1.0.6 — complete presentation implementation plan

**Status:** IMPLEMENTED / RECERTIFICATION REQUIRED — the prior 14-theme candidate was found non-compliant with JIG-106-FR-02 and AGENTS.md because it exposed upstream dark-only Astryx Gothic. The implementation has been remediated back to the governed 13-theme catalogue; exact permanent certification must be refreshed before merge.  
**Target release:** v1.0.6 patch.  
**Functional authority:** `docs/requirements/planning-workbench.md` JIG-106-FR-01 through JIG-106-FR-07.  
**Technical authority:** `docs/architecture/technical-solution.md` JIG-106-SD-01 through JIG-106-SD-07 and §6.  
**UI authority:** `docs/design/ui-solution.md` v0.19.  
**Brand/theme authority:** `docs/design/brand-and-theme.md` v0.19.  
**Repository governance:** `AGENTS.md`.

## 1. Scope and non-negotiable architecture

v1.0.6 is a presentation/browser correction and expansion. It changes secondary-screen geometry, application theme selection/resolution, semantic theme coverage, in-application wordmark paint, reminder presentation and Settings appearance controls.

It **does not** change:
- canonical `Task` or `TaskCommand`;
- Planner ordering, completion, rollover or date semantics;
- SQLite schema/revision behavior;
- HTTP protocol/admission;
- portable records or repository/Git synchronization;
- installer/service ownership;
- release mechanics.

Do not introduce DTO/ViewModel hierarchies, service/repository classes, state frameworks, workflow engines, a second theme engine, runtime theme compilation/fetching, another UI toolkit, private Astryx selectors/properties, `!important`, theme-name branches in feature CSS, or unchecked typing workarounds.

`package.json.version` stays **1.0.5** on the implementation branch. v1.0.6 version metadata belongs only to the later governed `release/v1.0.6` transition.

## 2. Current-state facts the implementation must replace

1. `ui/src/styles.css` already has the correct base `max-width: 50rem` for History/Settings but incorrectly removes it below 73rem.
2. Settings already uses a fluid two-column grid at wide composition and one column below 73rem.
3. The application already has one Astryx root `Theme`, but theme family is fixed to Jig and the existing browser-local value combines only `system|light|dark`.
4. Current theme authoring is one Jig source + generated `jig.js/jig.css`; v1.0.6 expands that through Astryx's existing theme build path rather than replacing it.
5. Current product aliases contain Jig-specific Ink/Amber values that must become palette-independent semantic mappings for multi-theme support.
6. The header currently renders two fixed-color external SVG wordmarks and switches them by Light/Dark; those assets cannot consume active application theme variables.
7. `ReminderMonitor` currently delivers Toast while visible and browser Notification while hidden; v1.0.6 requires browser Notification only.
8. Settings already contains the Appearance area and browser-notification permission row; appearance expansion belongs there rather than creating a new surface.

## 3. Execution order

Implement in this order so each step leaves one semantic owner:

1. J106-IMP-01 — continuous secondary-screen measure.
2. J106-IMP-02 — theme packages, authored theme set, the one shared product-token authoring helper, build/check path and catalogue source data.
3. J106-IMP-04 — apply/audit that shared semantic contract and complete color/state coverage across all themes/features.
4. J106-IMP-03 — independent ThemePreset/AppearanceMode state and persistence.
5. J106-IMP-07 — Settings-only appearance controls.
6. J106-IMP-05 — semantic in-application wordmark.
7. J106-IMP-06 — browser Notification-only reminders.
8. J106-IMP-08 — full certification, documentation and regression closure.

IMP-05 and IMP-06 may be implemented independently after their owners are available; do not merge partially complete theme work as a release candidate before IMP-08.

## J106-IMP-03 — Independent ThemePreset and AppearanceMode

**Closes:** JIG-106-FR-03 / JIG-106-SD-03.

**Primary files**
- new `ui/src/appearance.ts`
- `ui/src/app.tsx`
- `ui/src/settings.tsx`
- architecture/browser tests

**Required implementation**
1. Move appearance types/guards out of `settings.tsx`.
2. Define exactly:
   - `ThemePreset` as the 13 literal IDs from IMP-02;
   - `AppearanceMode = "system" | "light" | "dark"`.
3. `appearance.ts` owns:
   - both guards;
   - the exhaustive theme registry/catalogue;
   - storage keys;
   - read/write helpers with best-effort localStorage failure handling.
4. Storage keys:
   - `jig-theme-family` → valid ThemePreset, default `jig`;
   - `jig-appearance-mode` → valid AppearanceMode, default `system`.
5. Backward compatibility:
   - if new appearance key is missing/invalid, read legacy `jig-theme`;
   - accept legacy `system|light|dark`;
   - any successful write to the new appearance key removes legacy `jig-theme` best-effort;
   - write `system` explicitly rather than encoding System as key absence.
6. App owns exactly one `themePreset` state and one `appearanceMode` state.
7. Root ownership is exactly:
   `<Theme theme={themeRegistry[themePreset].theme} mode={appearanceMode}>`.
8. Do not add `matchMedia`/resolved-mode React state. Astryx owns System resolution.
9. Theme/mode changes must not modify destination, displayed week, workspace/draft, drag state or canonical data.

**Verification**
- invalid/missing storage safely defaults;
- legacy appearance value migrates behavior without losing preference;
- forced Light/Dark stay explicit;
- in System, change Playwright emulated color scheme while the same mounted app remains open: computed colors change, ThemePreset does not, and Planner/workspace state remains unchanged;
- localStorage failures do not break in-memory theme switching.

## J106-IMP-04 — Complete semantic re-theming and state precedence

**Closes:** JIG-106-FR-04 / JIG-106-SD-04.

**Primary files**
- shared theme-authoring product-token owner
- all 13 authored/wrapper theme sources
- `ui/src/styles.css`
- affected UI components only where a raw/fixed color or wrong semantic owner exists
- architecture/browser tests

**Shared Jig product aliases**
Implement the exact JIG-106-SD-04 aliases:
- today border/text → teal semantic family;
- selected Task bg/border → info semantic family;
- active nav → neutral + primary text;
- drag bg/border → active theme accent family;
- High/Normal/Low → error/secondary/success;
- healthy status → success family;
- hover/pressed → opaque Task-surface tints toward the active theme's `--color-tint-hover` (5%/10% or equivalent layered result), never a translucent replacement background;
- Task border → emphasized border;
- brand primary/accent → icon-primary/icon-accent unless the theme source must choose an equivalent accessible same-role value;
- Task surface → the exact per-theme elevated source table in JIG-106-SD-04; the **Jig** preset retains its existing Light White / Dark Ink 800 pair and must not regress to generic Jig surface Ink 900.

The shared product-token owner may take only the small per-theme values that genuinely differ (notably Task surface). Do not create a runtime theme DTO or duplicate token maps in feature code.

**Complete community color inventory**
Every community source must explicitly own all Astryx color families required by JIG-106-SD-04:
- body/surface/card/popover/muted/inverted;
- accent/accent-muted/on-accent/neutral;
- text primary/secondary/disabled/accent and on-fill roles;
- icon primary/secondary/disabled/accent;
- overlay/hover/pressed;
- ordinary/emphasized border;
- skeleton/track/shadow/tint;
- info/success/warning/error strong + muted + on-fill + text/icon/border;
- blue/cyan/gray/green/orange/pink/purple/red/teal/yellow background/border/icon/text roles.

Do not leave inherited Neutral colors in a community theme's application color inventory.

**Feature-state owners**
Enforce the JIG-106-SD-04 exhaustive owner table. In particular:
- page/Planner/header use body semantics;
- Task/History rows use `--jig-task-surface`/border;
- popovers/dialogs/menus/fields remain Astryx semantic surfaces;
- completion remains check + line-through + secondary text, not color-only;
- pending/retrying use warning family and explicit label;
- sync issue/error uses error family and explicit copy;
- unknown uses muted/secondary/explicit Status;
- no literal Jig hue is treated as universal across themes.

**Precedence**
Tests must prove:
1. focus remains independently visible over selection/priority;
2. drag owns transient interaction surface/border;
3. selection owns non-drag selected surface/border;
4. priority leading cue survives selection/focus/drag;
5. today remains date/header state;
6. operational status never becomes Task state.

**Architecture guard**
- palette literals allowed only in governed theme/palette sources and fixed external brand assets;
- reject raw color literals in `styles.css` and product components;
- reject theme-name selectors/branches in feature CSS/components;
- reject private Astryx selectors/custom properties.

**Contrast/semantic acceptance**
For every one of 13 themes in forced Light/Dark and System-resolved Light/Dark:
- normal/status text meets 4.5:1 where normal-text AA applies;
- content on accent/status fills meets 4.5:1;
- focus/current-day/selection/drag state boundary is >=3:1 where color is the state signal, or retains an independent non-color affordance;
- Task surface differs visibly from Planner canvas;
- today/selection/drag/priority/status do not collapse to one computed treatment.
